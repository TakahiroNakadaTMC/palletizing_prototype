## 3. 主要ロジックと実装機能

### 上載せ平パレットの支持安定性（2026-11-05）

- 上載せは下側と同寸法・同XY位置、均等荷重で重心をパレット中心とする。
  [共通幾何判定](../constraints/top_support.py)で、上段箱に隠れた上面を除去し、
  パレット範囲内の最高接触上面から3 mm以内の露出支持面を抽出する。
- 原則荷山外周4隅を覆う支持面がパレット下面と接触すれば、中央の空間は許容する。
  箱DBの `top_support_points`（4/5、未指定時TP331/TP-331は5）で必要位置を設定でき、
  5点指定の接触支持箱があればパレット中心も必須。
- 四隅が埋まっていても、1箱で複数隅を覆う場合は接触支持領域全体の外接短辺670 mm以上が必要。
  別々の4箱で各隅を覆う場合にはこの条件を要求しない。四隅が欠ける場合は、接触支持領域の外接矩形の
  前/奥と左/右の4辺すべてでそれぞれ連続670 mm以上を要求する。短辺側も必要。
  途中の長い支持線や外接短辺の長さだけでは不可。
  複数箱の連続辺も含み、空間やパレット外の辺は加算しない。重心は支持面凸包の内部が必須（辺上はNG）。
- 支持凸包面積は設定上限 `max_x_span × max_y_span` の65%以上（境界を含む）を必須とする。
  凸包の面積重心とパレット中心のずれは各方向で設定幅の1/4未満（境界NG）。
  設定上限矩形はパレット中心に配置する。実際の荷山外形・パレット寸法を面積の分母にせず、
  内部空間は凸包に含む。実接触面積率や高さ/支持幅比の追加条件ではない。
- 単載候補フィルター、混載候補評価、最終サマリーで同じ条件を使う。
  `level_top_four_corners` は呼出互換のため名前を維持し、既に安定した例外配置を削らない。
  不安定なら高い箱を除外した候補を高さ降順で確認し、最初の安定案を返す。
  安定案がなければ元配置を保持し、最終サマリーで明示的にNGを報告する。
- `summary.top_support` に支持高さ・箱番号/型番・接触領域・必要点数・四隅/中央充足・
  支持多角形・連続X/Y辺長・`opposing_edge_lengths_mm`（front/back/left/right）・
  `opposing_support_axis`（例外の辺条件を満たす場合XY、それ以外は空文字）・例外適用・違反を記録する。
  既存の箱底面支持率等は維持する。
  `support_polygon_area_mm2`・`support_area_ratio`・`support_centroid`・`centroid_offset_mm`、
  `reference_max_x_span_mm` / `reference_max_y_span_mm`・`multi_corner_boxes`・`contact_short_side_mm`
  に面積・偏り・複数隅の判定根拠を出力する。支持なしでは面積0、重心/ずれはnull。
- 支持は剛体・静的荷重の幾何近似。3 mm差の同高扱いは実接触、耐荷重・たわみの保証ではない。
- 今回の更新では単載の端数最上段を許可し、配置数 → 四隅支持 → 低高さ → 端数段なし → 外形占有率 →
  X長手 → 中央接触の順で比較する。短い分割ブロックを中央寄せし、四隅＋中央の定形5点候補を追加した。
  aisin_5専用の未配置ルールは追加していない。`othics_9` の最大Xだけ、ユーザー指定の1135 mmへ訂正した。
  最新のケース別結果は [検証レポート](../supervisor/reports/validation_report.md) を参照。

### ケース別寸法設定（2026-11-03）

`PalletSpec` は `length=1200`、`width=1000`、`height=130`（本体L/W/H）と、
`max_x_span=1360`、`max_y_span=1100`、`max_height=1200`（荷山最大L/W/H）を保持します。
6項目は正の有限数値で、荷山最大Lは最大W以上です。最大外形は境界値を含みます。
本体Hを積載高さから差し引かず、内部Z座標は引き続きパレット上面を0とします。
固定800 mm下限とはみ出し許容値・670 mm例外は撤廃しました。
旧設定キーは読み込み時に無視し、結果には出力しません。
現在のCLIでは、ケースの `pallet_id` からパレットDBの本体L/W/Hを取得します。
旧ケースに本体寸法が残っていてもDB値を優先します。
ケース固有の荷姿上限（`max_x_span`、`max_y_span`、`max_height`）は維持します。
`PalletSpec` を直接生成する場合の本体Hの既定値は130 mmです。
下限廃止により、小さい完全層を使って従来より多く配置できる場合があります。
最下段は、本体底面とパレットとの交差面積で85%以上の支持を候補・最終判定で確認します。
`summary.overhang_mm`（left/right/front/back）、`warnings`、
`total_height`（本体H＋実際の荷物H）を出力します。警告は制約NGとは別です。
体積充填率は従来どおり箱の外形体積合計÷（パレットL×W×荷山最大H）です。
はみ出しや嵌合沈み込みがあるため100%を超える場合があり、合否判定には使いません。
これらの幾何判定は実物の安定性を保証しません。旧結果は再計算・独立検証してください。

### 下段隅の被覆判定（2026-10-27）

- `_covered_support_corners` は上段本体底面に含まれる直接支持箱の箱・蓋外形の隅を集め、
  XY辞書順の代表点で重複除外する。位置数2以上が必要で、各下段箱での隣接2隅は要求しない。
- `_support_corners_allowed` はパレット直置きを免除する。
  外嵌め蓋付きTP箱と非TP箱は、`_column_stack_is_allowed` の既存条件を満たす場合のみ免除する。
  同じ規格であることだけでは免除しない。既存の支持率・サイズ制約等は引き続き必要。
- 行詰め・EP等の候補判定、単載の積み上げ、および `calculate_summary` で確認する。
  四隅高さ調整やセンタリング後も最終結果を再確認し、違反を有効な荷姿として扱わない。
- 同一配置の単載で、コラム免除のない蓋が本体から片側0.01 mmを超えて張り出す場合は、
  上段底面が下段外形の隅に届かないため、候補比較時から最大1段に制限する。
- 独立バリデータは出力座標から支持箱と被覆位置を再計算し、違反時に上段箱・支持箱番号、
  被覆座標、重複除外前後の数を報告する。記録済み `supported_by` やエンジンの合否には依存しない。
- XY許容差は各方向0.01 mm（数値誤差1e-9 mmを追加）。支持高さ・重なり判定の既存許容差は変更しない。
  実接触や物理的安定性を保証する判定ではない。詳細は[制約仕様](../constraints/constraints.md)を参照。

1. **単載エンジン (`palletize_single`)**:
   - 0度/90度グリッドおよびスプリット（レンガ）分割パターンを自動生成・比較。
     分割領域の列数・行数を減らした候補も列挙し、位置・寸法・回転が同じ候補は重複除去する。
   - 長方形4箱で中央を空ける風車（ロの字）を最大1候補、従来候補の末尾に追加する。
     `_generate_pinwheel_pattern` の座標生成を混載と共有し、複数組の風車・自由座標探索は追加しない。
     投入4箱未満、積載可能段数0、正方形、長辺＋短辺が最大X/Y幅を超える場合は追加しない。
   - 荷山最大外形・底面支持率・上載せ支持安定性を確認し、候補ごとに
     完全層数と、最上段に載せられる残数の部分集合を算出する。
     **総配置個数が最大 → 四隅支持あり → 荷姿高さが最小 → 端数段なし → 外形占有率が最大 → X長手 → 中央接触**の順に選ぶ。
     端数段なしは各段の箱数が同数であること。配置数・四隅・高さが同点の場合だけ優先する。
     完全同点は候補順を維持する。
     外形占有率は `(荷姿X幅 × 荷姿Y幅) / (ケースの最大X幅 × 最大Y幅)`。
     箱・蓋の外接矩形を使い、中央空間も含める。体積充填率・安全性とは異なり、出力JSONの既存項目は変更しない。
     現時点の最良案以下と確定した完全層候補は、詳細な支持率・四隅判定を省略する。
     荷姿高さは `箱高さ + 蓋厚み + (段数 - 1) × (箱高さ + 蓋厚み - 嵌合深さ)`。
   - 部分集合の組合せが4096以下なら全列挙し、それ以上は最大16候補の削除探索で絞る。
     最上段の支持を下段外形も含めて検証する。任意の配置の大域最適解は保証しない。
   - 定形5点候補は外周4隅と中央を3×3範囲へ置く。分割配置の短いブロックは中央寄せする。

   - X/Y外接幅がケースの最大L/W以下であることを確認（固定下限なし）。
   - パレット中央への自動センタリングオフセット計算。
   - はみ出しは確認情報。最下段の支持率85%以上を別途確認する。
   - 勘合深さ `fitting_depth` を考慮した最大段数・Z座標計算。
   - 完全な下段で同じX/Y位置・回転角度のパターンを反復し、最上段だけその部分集合を許可する。
     段ごとの配置反転は行わない。
   - 最上段のみ、支持条件を満たす端数配置を許可し、配置不可の残箱を未配置として返す。
     下限廃止により少数投入でも小さい完全層を選べる。配置後に中心を揃え、
     共通後処理・制約検証を適用する。

2. **混載エンジン (`palletize_mixed`)** — MSP-EPハイブリッド方式（2026-09-23改訂）:
   - **探索範囲 (`_determine_mixed_envelope`)**: ケースの最大L/Wをそのまま使う（境界値を含む）。
     Y範囲を最小箱寸法の整数倍に固定せず、異なる行奥行きの合計も試す。支持率とセンタリングは別途確認する。
   - **層候補の比較 (`_choose_layer_height` / `_mixed_layer_candidate_score`)**: 配置高さに収まる箱を高さごとに
     パッキングし、四隅の揃い方、配置数、次段の高さ余裕を比較して採用する候補を決める。
   - **Phase A - 四隅アンカリング（廃止）**: `_anchor_corners` による各層四隅への先置きは行わない。
     先置きが行分割詰めを妨げ、箱間に隙間を作ったため無効化された。
     2026-11-05追加の `_corner_column_candidates` は上段用の別枠候補であり、
     各層の四隅へ強制的に先置きする旧処理とは異なる。
   - **Phase B - 行分割＋FFD詰め (`_row_free_intervals` / `_fill_row_intervals`)**: 層をY方向に箱の代表寸法で
     行(Row)分割し、既配置箱を障害物として扱いながら空きX区間をFirst-Fit-Decreasingで充填
     （Module-Aware Strip Packing）。
   - **複数の行組み合わせ (`_mixed_layer_candidates`)**: 探索途中の配置を最大16通り残し、候補ごとに箱の残数を管理する。
     新しい探索では344 mmと345 mmのような近い行奥行きも区別する。従来の行詰め結果も候補に含め、四隅・配置数で比較する。
   - **風車配置候補 (`_pinwheel_layer_candidates`)**: 同一矩形4箱を交互に回転して正方形の四隅を覆う候補を追加する。
     670 × 335 mm箱の混載では、例外を使わず1005 × 1005 mmの荷姿を作れる。
     通常の行詰めを置き換えるものではなく、支持率・段積み条件も確認する。
   - **上段までの比較 (`_palletize_mixed_layout`)**: 最下段候補を最大16通り試し、それぞれ上段まで積む。
     上載せ支持調整後に再センタリングし、全制約の合否を優先してから、
     最終配置箱数・四隅支持・低高さ・端数段なし・外形占有率・X長手・中央接触の順で選ぶ。
     全組み合わせの探索ではないため、最大配置数を保証するものではない。
   - **Phase C - Extreme Points補完 (`_ep_fill_layer`)**: 行詰めで埋まらない残渣スペースは、既配置箱の
     右端・下端から動的に候補座標を生成して追加充填。
   - **配置後の支持調整 (`level_top_four_corners`)**: 全層の配置後に上載せ支持安定性を確認する。
     不安定なら上面高さ別に高い箱を除外した候補を確認するため、最終配置数が減る場合がある。
   - 候補追加時はセンタリング後のパレット支持率を確認し、最終判定でも再確認する。
   - **配置可否判定 (`_try_place_at`)**: 境界チェック・2D重なりチェックに加え、2層目以降は以下を必須とする:
     - 支持面判定: 直下段箱との接地面積比率85%以上（空中浮きの完全排除、`_support_ratio`）。
     - **下段オーバーサイズ制約 (`_is_oversized_support` / `_has_oversized_support`)**:
       直接支持している下段箱のいずれかが、上段箱よりも幅・奥行きの**両方とも1.0mmを超えて**大きい場合は配置不可とする。
       上段箱が下段箱の縁からずれて不安定な段積みとなり荷崩れする危険があるため（同一サイズ・片方のみ
       大きい場合は許容）。`supervisor/validate.py` にも同等の独立検証項目を追加済み。
   - **レイヤーループ**: 箱在庫切れ・次層が積載高さ超過・当該層が1個も配置できない（デッドロック回避）の
     いずれかでのみ終了。旧実装にあった「層自身の四隅不一致で即break」ロジックは撤廃済み（打ち切り防止）。
   - 回転（0°/90°）の一致を強制する制約は設けていない（自由に選択可）。

3. **積み順決定 (`assign_loading_orders`)**:
   - トポロジカルソート
     $(Z_{base} \text{昇順} \to Y_{base} \text{昇順} \to X_{base} \text{昇順})$
     により、下段優先・干渉フリーな積載順序 `order` (1..N) を付番。
   - 支持している下段箱の `order` リスト（`supported_by`）を記録。

## 4. 実行方法 (CLI)

### 配置結果の座標基準

結果JSONは `coordinate_reference: "combined_footprint_min_xy_top_z"` を記録します。
`position.x/y` は回転後の箱本体と蓋を合わせた外接形状の最小角、`position.z` は蓋込み上面です。
箱本体寸法は従来どおり `dimensions.width/length`、蓋込み高さは `dimensions.height` に保持します。
内部のパレタイズ計算では箱本体底面基準を使用し、シリアライズ時に結果座標へ変換します。

`coordinate_reference` のない既存結果は、従来の箱本体底面角の座標として扱います。

```bash
# 単一テストケースの実行
python3 algorithm_programmer/cli.py test_programmer/test_cases/aisin.json

# 結果をJSONファイルに出力
python3 algorithm_programmer/cli.py \
  test_programmer/test_cases/aisin.json \
  -o tester/results/result_aisin.json
```
