## 3. 主要ロジックと実装機能

1. **単載エンジン (`palletize_single`)**:
   - 0度/90度グリッドおよびスプリット（レンガ）分割パターンを自動生成・比較。

   - 長辺荷姿幅 $800\text{mm} \le X_{span} < 1360\text{mm}$、
     短辺荷姿幅 $800\text{mm} \le Y_{span} < 1100\text{mm}$ の境界フィルタリング。
   - パレット中央への自動センタリングオフセット計算。
   - 最下段箱の回転後底面辺が335 mm以下の場合、蓋を含む外形の片側はみ出しを
     `PalletSpec.max_small_edge_overhang_mm` 未満に制限（既定30 mm）。
   - 勘合深さ `fitting_depth` を考慮した最大段数・Z座標計算。
   - 偶数/奇数段の反転によるインターロッキング（荷崩れ防止）。

2. **混載エンジン (`palletize_mixed`)** — MSP-EPハイブリッド方式（2026-09-23改訂）:
   - **探索範囲 (`_determine_mixed_envelope`)**: X/Yの許容上限から既存の1 mmの余裕を引いた範囲を使う。
     Y範囲を最小箱寸法の整数倍に固定せず、異なる行奥行きの合計も試す。支持率・センタリング・小辺はみ出し制約は別途確認する。
   - **層候補の比較 (`_choose_layer_height` / `_mixed_layer_candidate_score`)**: 配置高さに収まる箱を高さごとに
     パッキングし、四隅の揃い方、配置数、次段の高さ余裕を比較して採用する候補を決める。
   - **Phase A - 四隅アンカリング（廃止）**: `_anchor_corners` による各層四隅への先置きは行わない。
     先置きが行分割詰めを妨げ、箱間に隙間を作ったため無効化された。
   - **Phase B - 行分割＋FFD詰め (`_row_free_intervals` / `_fill_row_intervals`)**: 層をY方向に箱の代表寸法で
     行(Row)分割し、既配置箱を障害物として扱いながら空きX区間をFirst-Fit-Decreasingで充填
     （Module-Aware Strip Packing）。
   - **複数の行組み合わせ (`_mixed_layer_candidates`)**: 探索途中の配置を最大16通り残し、候補ごとに箱の残数を管理する。
     新しい探索では344 mmと345 mmのような近い行奥行きも区別する。従来の行詰め結果も候補に含め、四隅・配置数で比較する。
   - **上段までの比較 (`_palletize_mixed_layout`)**: 最下段候補を最大16通り試し、それぞれ上段まで積む。
     四隅高さ調整後に再センタリングし、寸法・四隅などの合否、最終配置箱数、最高高さの順で選ぶ。
     全組み合わせの探索ではないため、最大配置数を保証するものではない。
   - **Phase C - Extreme Points補完 (`_ep_fill_layer`)**: 行詰めで埋まらない残渣スペースは、既配置箱の
     右端・下端から動的に候補座標を生成して追加充填。
   - **配置後の四隅高さ調整 (`level_top_four_corners`)**: 全層の配置後に最上段四隅の高さを確認する。
     高さが揃わない場合は低い角に合わせて高い箱を除外することがある。この後処理は四隅への先置きではなく、
     配置済みの箱を削る場合があるため、最終配置数が減ることがある。
   - 最下段の335 mm以下の辺に対するパレット端はみ出し制限は、候補追加時と配置位置調整時に適用する。
   - **配置可否判定 (`_try_place_at`)**: 境界チェック・2D重なりチェックに加え、2層目以降は以下を必須とする:
     - 支持面判定: 直下段箱との接地面積比率85%以上（空中浮きの完全排除、`_support_ratio`）。
     - **下段オーバーサイズ制約 (`_is_oversized_support` / `_has_oversized_support`)**:
       直接支持している下段箱のいずれかが、上段箱よりも幅・奥行きの**両方とも1.0mmを超えて**大きい場合は配置不可とする。
       上段箱が下段箱の縁からずれて不安定な段積みとなり荷崩れする危険があるため（同一サイズ・片方のみ
       大きい場合は許容）。`supervisor/validate.py` にも同等の独立検証項目を追加済み。
   - **レイヤーループ**: 箱在庫切れ・次層が積載高さ超過・当該層が1個も配置できない（デッドロック回避）の
     いずれかでのみ終了。旧実装にあった「層自身の四隅不一致で即break」ロジックは撤廃済み（打ち切り防止）。
   - 回転（0°/90°）の一致を強制する制約は設けていない（自由に選択可）。

3. **積み順決定 (`assign_loading_orders`)**:
   - トポロジカルソート
     $(Z_{base} \text{昇順} \to Y_{base} \text{昇順} \to X_{base} \text{昇順})$
     により、下段優先・干渉フリーな積載順序 `order` (1..N) を付番。
   - 支持している下段箱の `order` リスト（`supported_by`）を記録。

## 4. 実行方法 (CLI)

### 配置結果の座標基準

結果JSONは `coordinate_reference: "combined_footprint_min_xy_top_z"` を記録します。
`position.x/y` は回転後の箱本体と蓋を合わせた外接形状の最小角、`position.z` は蓋込み上面です。
箱本体寸法は従来どおり `dimensions.width/length`、蓋込み高さは `dimensions.height` に保持します。
内部のパレタイズ計算では箱本体底面基準を使用し、シリアライズ時に結果座標へ変換します。

`coordinate_reference` のない既存結果は、従来の箱本体底面角の座標として扱います。

### ハンド形状モデル（第1段階）

[hand_profile.py](hand_profile.py) は設備共通設定の検証と、蓋込み角基準のL字ハンド干渉形状の生成を行います。
設定は [hand_profiles.json](hand_profiles.json)、編集・確認方法は
[ハンド設定画面の説明](../box_research/README.md#ハンド設定形状確認第1段階) を参照してください。

- `schema_version: 1`、設備ID・名前・共通の形状パラメータのみ保存。箱別設定、動作パラメータ、プレビュー選択は保存しない。
- 箱ローカルX/Yは既存の回転0°と同じDBのW/L。4角を0°/90°/180°/270°の剛体回転で表す。
- 本体は固定長の2本の直方体、爪は箱・蓋外形の各辺の寸法から位置を計算する。
- `envelope` は本体・爪の固定寸法の干渉形状。爪位置だけが箱寸法に追従し、開閉による寸法変化・開閉量は扱わない。
- 返すXYZは最終配置の蓋込み最小XY・上面Zに対する相対座標。
- プレビュー対象の把持角・ハンド向きを返すが、`feasibility_checked: false`。動作経路は生成しない。

形状プレビュー自体は配置順や結果を変更しません。現在は以下の静的判定・順序生成を配置エンジンにも接続しています。
共通の形状モデルを利用する静的判定を [hand_collision.py](hand_collision.py) に追加しています。
`check_static_hand` は既存結果・保存済み設備設定・order・手動選択の角を受け取り、
先行箱/蓋・パレット・把持対象への実食込み、余裕不足、把持角座標、ハンド姿勢を返します。
元データは変更せず、`trajectory_checked: false` / `order_changed: false` を明示します。
`select_static_corners` は同じ判定処理で全箱の4角を調べ、固定優先順で干渉しない最初の角を選びます。
箱ごとに `selected` / `blocked` / `out_of_range` を返し、4角の判定・使用した設備設定のスナップショットを保持します。
設定範囲外のみ `HandGeometryRangeError` として角単位で扱い、入力・設定不正はバッチエラーとして呼出元へ伝えます。
先行する未選択箱も障害物に含め、元の位置・順番は変更しません。
統合ビューアから [保存済み把持角の表示と手動確認](../visualizer/README.md#ハンド干渉の静的確認) が可能です。
自動選択・順序再生成の画面操作は正式結果への統合後に削除しました。内部関数・APIは検証用に維持しています。
[hand_sequence.py](hand_sequence.py) の `generate_hand_sequence` は支持関係を形状と照合し、
結果の `layer_index`（0が最下層、各箱に0以上の整数が必須）を層の境界として固定します。
最上層から一層ずつ、上段を支持していない全箱の4角を調べ、残存箱への干渉がなく設定範囲内の
「箱＋把持角」を、把持角の `reference_position` のX降順・Y降順・元番号昇順・固定角順で比較します。
箱の最小XYではなくパレット座標系の蓋込み外形角に置くハンド基準点を使用し、Zは優先キーにしません。
取り出すたびに再判定し、選択した角・姿勢を逆順の配置でも維持します。
現在の層で停止した場合は下層を先に取り出しません。固定配置順の角選択は変更しません。
形状から求めた直接支持箱が同じ層または上層となる場合は入力エラーです。
全箱完了時だけ逆順の配置を生成し、支持関係と配置時点の干渉を再検証します。
`depalletizing` / `palletizing` の各項目は `original_order` で箱を識別し、
`step` は新しい順番、`layer_index` は元の層、配置側の `supported_by` は新しいステップ番号です。
配置は層番号の昇順で、一層をすべて配置してから次の層へ進みます。
途中停止時は `status: "stalled"` と残存箱の理由を返し、`palletizing` は空です。
`_check_pose` の `obstacle_orders` によって元番号に依存せず障害物集合を渡し、手動・自動選択の判定を再利用します。
### 正式な配置結果への組み込み

`Palletizer.assign_loading_orders` は逆順のハンド順序生成を実行し、再検証済みの順番を正式な
`order` / `supported_by` として返します。Z/Y/X順は一時的な識別番号と同順位時の決定にだけ使用します。
配置位置・箱の回転・層は変えません。全箱の順番が成立しなければ `HandSequenceError` を送出し、
元順へのフォールバックや部分的な配置計画の出力は行いません。例外の `result` には停止理由を保持します。

- `Palletizer(..., hand_profile=profile)` で設備設定を渡せます。省略時は保存済み設定を読み込みます。
- 保存設備が1件なら自動選択。複数件なら明示指定が必要で、先頭設備への暗黙の切替はしません。
- CLIは `--hand-profiles` で設定ファイル、`--hand-profile-id` で設備IDを指定できます。
  通常のテストランナーも同じCLIを通るためハンド判定が適用されます。
  `tester/run_tests.py` にも同じ設備指定オプションを渡せます。CLIが失敗したケースは過去の結果を読み直さず、
  エラーとして集計し、一括実行も非ゼロ終了します。
- 箱ごとの `hand_grasp` に `corner_id`、`reference_position`（パレット座標XYZ、mm）、
  `hand_yaw_deg`、`static_verified` を保存します。
- 結果の `hand_sequence` に使用設備のスナップショット、優先規則、層規則、
  `reverse_verified: true`、`trajectory_checked: false` を保存します。別の結果ファイルは作りません。
- 順序生成失敗時、CLIは非ゼロ終了し結果ファイルを新規作成・上書きしません。
  同じ出力先に過去の結果があればそのまま残るため、今回成功した結果とは扱わないでください。
- 既存の保存結果は自動変換しません。CLIまたはテストランナーで再実行した結果から適用されます。

専用ハンドの自動切替と経路判定は未実装です。
進入・退避の詳細設定と経路判定は後工程です。位置付近の判定だけで経路成立を保証しません。
出力は内部プレビュー用であり、ロボット向けTCP/姿勢データではありません。

```bash
# 単一テストケースの実行
python3 algorithm_programmer/cli.py test_programmer/test_cases/mixed_tp_same_height.json

# 結果をJSONファイルに出力
python3 algorithm_programmer/cli.py \
  test_programmer/test_cases/mixed_tp_same_height.json \
  -o tester/results/result_mixed_tp_same_height.json
```
