## 1. 概要

本レポートは、パレタイズアルゴリズム試作プロジェクトにおいて対象とする**工業用TP規格コンテナ**および**代表的非TP規格箱（折りたたみコンテナ・一般通い箱・番重）**の寸法・嵌合（かんごう）深さ・リブ仕様を調査・整理した成果物です。

構築されたデータベースは [box_db.json](box_db.json) に格納されています。

### 箱DBビューアの読み込み・保存

- [箱・蓋DB統合ビューア](db_viewer.html) は
  [box_db.json](box_db.json) と [lid_db.json](lid_db.json) をマスタとし、
  起動時に `GET /api/boxes`・`GET /api/lids` からキャッシュを使わず取得します。
  localStorageやHTML内の固定データは使用しません。
- `python box_research/serve_viewer.py` を起動すると、選択入力なしで
  `http://localhost:8081/` が開きます。
  ポート使用中は8082～8090を試すため、コンソールに表示されるURLを確認してください。
  HTMLファイルの直接表示には対応しません。
- 初期表示は箱DBです。タブはページ遷移をせず切り替えるため、編集・追加・削除や入力途中の内容を保持します。タブ切替で自動保存はしません。
- 箱DBは採用・不採用を管理しません。登録箱数・TP規格箱数・非TP規格箱数を集計し、検索と規格別フィルターは表示だけに適用します。箱の寸法はL・W・Hの個別列で表示し、嵌合深さ・上縁幅・モジュール比・説明も一覧から確認できます。蓋DBの機能は維持し、蓋の色・説明と、外嵌め／内嵌め件数も表示します。
- 旧URLの `/box_db_viewer.html` は `/#boxes`、`/lid_db_viewer.html` は `/#lids` に転送します。既存ブックマークを引き続き利用できます。旧箱HTML内の独立した編集処理は削除し、統合画面への案内に統一しています。
- 「box_db.json に保存」は削除していない登録箱すべて、「lid_db.json に保存」は蓋DBを保存します。JSONコピー・ダウンロードも登録箱すべてが対象で、検索・絞り込みによって箱が除外されることはありません。不要な箱は削除してから保存してください。既存の箱DBの保存形式・登録値は変更しません。
- 蓋の追加・変更は共有の編集中データに反映します。蓋ID変更・削除による互換蓋参照の更新や、未保存の蓋への参照などで連動保存が必要な場合は、他の未保存の箱の追加・編集・削除も含めて保存範囲を確認します。
- テストケースから参照されている蓋の削除・ID変更、および最後の「無蓋」の削除は禁止します。参照確認に失敗した場合は削除・ID変更を確定できません。
- 箱も `GET /api/box_references` でテストケースの参照を取得し、使用中の箱の削除・ID変更を禁止します。警告には該当テストケースのファイル名を表示します。
- 箱の保存時（蓋との同時保存・従来の保存APIも含む）はサーバーでテストケースを再確認し、保存済みの使用中の箱が消える保存を拒否します。参照取得に失敗した場合も保護を解除せず、エラーを表示します。未使用の箱は削除できます。既存の箱ID欄は従来どおり編集不可です。ID変更に相当するデータをAPIへ送った場合も、使用中の旧IDが消える保存を拒否します。
- テストケース側の採用・不採用（ケースを保存したまま実行対象を選別する機能）は変更しません。過去に箱DBへの保存対象から除外された箱を自動復元する機能はありません。
- 未保存状態を表示し、画面の再読み込み・終了時にはブラウザの警告を要求します（実際の警告表示はブラウザの仕様によります）。画面を離れると未保存の変更は失われます。明示的な再読み込みも確認後に編集を破棄します。
- 取得失敗時はエラーを表示して編集・保存を無効にします。保存中も変更を禁止し、保存失敗時は未保存の編集を保持します。自動ダウンロードで保存成功の代わりにはしません。

### 設定項目の定義と説明図の扱い

- `rib_thickness` の画面上の名称は **上縁幅（mm）**。
  上から見た外側の縁から開口部側の縁までの幅で、底面の厚みや側壁の肉厚ではありません。
  内寸の測定位置やテーパーの影響があるため、`（外寸−内寸）÷2` による自動計算はしません。
- `thickness` の画面上の名称は **蓋装着時の高さ増加量（mm）**。`蓋ありの箱の高さ − 蓋なしの箱の高さ` を入力します。蓋単体の全高や天板の肉厚ではありません。
- 保存キー・既存の登録値は変更しません。配置計算は従来どおり箱の高さに `thickness` を加えており、計算方式の変更はありません。
- 初回に追加した説明図は全点を見直すため、画面から外しています。対象は箱の外寸・嵌合深さ・上縁幅・モジュール比・互換蓋と、蓋の外寸・装着時の高さ増加量・嵌め方のすべてです。図案と画面内の配置をユーザーが確認するまでは再追加しません。

回帰テスト（リポジトリルートから実行）：

```powershell
python -m unittest box_research.serve_viewer_test -v
node --test box_research\box_db_viewer_test.cjs box_research\db_viewer_test.cjs
```

フロントエンドのテストはNode.js 18以降、追加パッケージ不要です。

## 2. TP規格コンテナの体系とモジュール仕様

### 2.1 TP規格とは

自動車産業・製造業物流において標準化されたプラスチックコンテナ規格（Toyota Plastic Box / JIS準拠）です。
**基準モジュール寸法（間口 335 mm × 奥行 335 mm）** を単位とし、倍数・分数関係にある異なる型番同士でも**底面のTP格子リブ構造により相互嵌合（スタッキング）が可能**です。

### 2.2 TP規格の平面モジュール関係

```text
 ┌───────────────┬───────────────┐
 │   TP-330系    │   TP-330系    │
 │ (335 x 335)   │ (335 x 335)   │  ──► 合計: 670 x 335 mm (TP-360系と完全一致)
 ├───────────────┴───────────────┤
 │           TP-360系            │
 │         (670 x 335)           │
 └───────────────────────────────┘

 ┌───────────────────────────────┐
 │           TP-360系            │
 │         (670 x 335)           │
 ├───────────────────────────────┤  ──► 合計: 670 x 503 mm (TP-460系と完全一致)
 │   TP-330系    │   TP-330系    │
 │ (335 x 335)   │ (335 x 335)   │
 └───────────────┴───────────────┘
```

| シリーズ | 外寸長さ L (mm) | 外寸幅 W (mm) | モジュール比率 | 嵌合互換性 |
| :--- | :---: | :---: | :---: | :--- |
| **TP-110系** | 168 | 168 | $0.5 \times 0.5$ | 4個で TP-330系 1個と同フットプリント |
| **TP-130系** | 335 | 168 | $1.0 \times 0.5$ | 2個で TP-330系 1個と同フットプリント |
| **TP-330系** | 335 | 335 | $1.0 \times 1.0$ | **基準モジュール** |
| **TP-340系** | 503 | 335 | $1.5 \times 1.0$ | 2個で TP-490系(1005x335) や 340系2列(503x670)と整合 |
| **TP-360系** | 670 | 335 | $2.0 \times 1.0$ | TP-330系 2個の上/下に嵌合段積み可能 |
| **TP-460系** | 670 | 503 | $2.0 \times 1.5$ | TP-360系(2x1) + TP-130系(2x0.5) や TP-340系(1.5x1) 2個とモジュール整合 |
| **TP-480系** | 838 | 503 | $2.5 \times 1.5$ | 特大モジュール |
| **TP-490系** | 1005 | 503 | $3.0 \times 1.5$ | 1200x1000 パレットの短辺(1000mm)にジャストフィット |

### 2.3 高さ体系と嵌合深さ (fitting_depth)

TP規格の高さは規格化されており、異なる高さの箱を組み合わせても段積み全体の高さを揃えやすくなっています。

- **代表的外寸高さ**:
  - **1型 (浅型)**: 103 mm
  - **1.5型 (中浅型)**: 149 mm
  - **2型 (標準型)**: 195 mm
  - **3型 (深型)**: 288 mm
- **嵌合深さ (`fitting_depth`)**:
  - TP-110 / 130系: **8.0 mm**
  - TP-330 / 340 / 360 / 460 / 480 / 490系: **10.0 mm**
- **段積み総高さの計算式**:
  $$H_{total}(N) = H_{bottom} + \sum_{k=2}^N (H_k - fitting\_depth_k)$$

### 2.4 上縁幅 (`rib_thickness`) の定義

**箱を上から見たときの、外側の縁から開口部側の縁までの幅**を入力します。樹脂単板の肉厚や、底面で測った片側側壁の厚みを表す項目ではありません。

同じ上面位置で測った外寸・開口寸法が左右対称であれば、その差の半分が目安になります。ただし、テーパーや内寸の測定位置によって一致しないため、有効内寸・底面内寸からの自動計算は行いません。

既存DBの値はそのまま保持します。過去に内寸差から推定された値については、この定義による実測済み値であることを保証するものではありません。更新時は上縁の測定位置を確認してください。

## 4. パレット (1200x1000) への適合性考察

1. **TP-340系 (503 × 335 mm)**:
   - 長辺 1200mm に対して $503 \times 2 = 1006\text{ mm}$、
     または $335 \times 3 = 1005\text{ mm}$、
     $335 \times 4 = 1340\text{ mm}$（1360mm未満許容枠内！）。
   - 短辺 1000mm に対して $335 \times 3 = 1005\text{ mm}$ や
     $503 \times 2 = 1006\text{ mm}$ は、いずれも許容スパン $1100\text{ mm}$ 未満。
     安定性の下限 $800\text{ mm}$ も満たす配置を選定する。
2. **TP-360系 (670 × 335 mm) & TP-460系 (670 × 503 mm)**:
   - 長辺 1200mm に対して $670 \times 2 = 1340\text{ mm}$（**長辺1360mm未満の許容枠を最大限に活かしたジャストフィット配置**が可能！）。
   - 短辺 1000mm に対して $503 \times 2 = 1006\text{ mm}$、
     または $503 + 335 = 838\text{ mm}$ は、
     いずれも $800\text{ mm} \le Y_{span} < 1100\text{ mm}$ を満たす。
3. **OC-50L (530 × 366 mm)**:
   - 長辺 1200mm に対して $530 \times 2 = 1060\text{ mm}$、
     短辺 1000mm に対して $366 \times 2 = 732\text{ mm}$（800mm未満のため単独列は工夫が必要）
     または $530 + 366 = 896\text{ mm}$（800mm以上1100mm未満に適合）。

## 5. 蓋データベース仕様（Phase 2 新規追加）

### 5.1 蓋DB の位置づけ

- **ファイル**: `box_research/lid_db.json`
- **目的**: パレタイズ対象箱に対応する蓋（フタ）の仕様を一元管理
- **用途**:
  - テストケース生成時の蓋選択肢の提供
  - パレタイズ結果への蓋情報付加（将来拡張）
  - UI上での箱-蓋関連性の可視化

### 5.2 蓋データ項目

各蓋について以下を管理：

| フィールド | 型 | 説明 |
| ----------- | ----- | ------ |
| `id` | string | 蓋識別子（例: `"LID-001"`） |
| `name` | string | 蓋の名称（例: `"TP-330系対応クリア蓋"`） |
| `type` | string | 蓋の規格タイプ（例: `"TP"`, `"OTHER"`） |
| `length` | float | 蓋の外寸長手方向 L [mm] |
| `width` | float | 蓋の外寸短手方向 W [mm] |
| `thickness` | float | 蓋装着時の高さ増加量 [mm]。蓋単体の全高や天板の肉厚ではない |
| `fit_type` | string | 蓋の嵌め方：`"外嵌め"` \| `"内嵌め"` \| `"なし"` |
| `color` | string（任意） | 色名。未設定は空文字、旧データの項目省略も可 |
| `description` | string | 対応規格や特徴の説明 |

**fit_type の定義**:

- `"外嵌め"`: 箱外側面と蓋で位置決め（標準方式、9個の蓋）
- `"内嵌め"`: 箱内壁面と蓋で位置決め
- `"なし"`: 蓋を使用しない場合（universal option、LID-010）

### 5.3 箱と蓋の互換性管理

Phase 2 で箱DB（`box_db.json`）を拡張し、各箱に `compatible_lids` フィールドを追加：

- **フィールド**: `compatible_lids` (array of string)
- **内容**: 当該箱に対応する蓋IDリスト
- **例**:

  ```json
  {
    "id": "TP-331",
    "name": "TP-331コンテナ",
    "compatible_lids": ["LID-001", "LID-002"]
  }
  ```

- **全体方針**: `compatible_lids` には箱に対応する実蓋のみを登録する。蓋DBの `type: "NONE"` は全箱共通の選択肢として扱い、箱ごとの互換リストには登録しない。

### 5.4 Phase 2 成果物一覧

| ファイル | 説明 |
| --------- | ------ |
| `box_research/lid_db.json` | 蓋DB本体（10個の蓋定義、fit_type フィールド付き） |
| `box_research/lid_db_viewer.html` | 旧蓋ビューア。サーバー経由のURLは統合画面の蓋DBタブへ転送 |
| `box_research/box_db_viewer.html` | 旧箱ビューア。サーバー経由のURLは統合画面の箱DBタブへ転送 |
| `box_research/db_viewer.html` | 箱・蓋の統合タブ画面（旧URLからは該当タブへ転送） |
| `box_research/db_viewer.js` | 共有の編集中データ・参照保護・保存処理 |
| `box_research/db_viewer.css` | 統合画面用スタイル |
| `box_research/serve_viewer.py` | 統合画面配信、旧URL転送、参照取得・検証、箱・蓋DBの保存API |

### 5.5 技術的ハイライト

- **REST API**: `serve_viewer.py` に蓋DB用エンドポイントを実装
  - `GET /api/lids` — 蓋DB全体を取得
  - `POST /api/lids/save_all` — 蓋DB全体を保存
  - `GET /api/box_references`・`GET /api/lid_references` — 箱ID・蓋IDごとの参照テストケース名を取得
  - `POST /api/databases/save` — 統合画面から箱・蓋を保存。`{"boxes": {...}}`、`{"lids": {...}}`、または両方を指定。互換蓋参照・テストケース参照を検証し、全ファイルを一時ファイルへ書き出してから置換します。置換失敗時は既に置換したファイルを元に戻し、エラーを返します。OS停止・プロセス強制終了に対する複数ファイルの完全なトランザクション保証ではありません。復元にも失敗した場合は、エラーに復旧用ファイルの場所を表示します。
- **UI**: HTML5 + Tailwind CSS で蓋管理画面を実装
  - 蓋統計（総数、外嵌め数、内嵌め数）を表示
  - 蓋の追加・編集・削除をモーダルフォームで実行
  - fit_type をドロップダウンで選択
- **データ永続化**: UTF-8 JSON ファイルとして直接保存（DB エンジン不要）

### 5.6 蓋の色情報（任意）

- `color` は「黒」「青」「透明」などを記録する任意の文字列項目。未設定は空文字 `""` とする。
- 蓋一覧の「色」列と追加・編集フォームに対応。項目のない旧データも未設定として扱う。
- 保存時に色情報を保持する。色名から既存データの色を推測して設定しない。
- 現時点ではパレタイズ計算・制約検証・3Dビューアの描画色には使用しない。
