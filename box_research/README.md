## ハンド設定・形状確認（第1段階）

```powershell
python box_research\serve_viewer.py
# [3] ハンド設定・形状確認を選択
```

起動済みの場合は `http://localhost:8081/hand_viewer.html` からも開けます。
別ポートで起動した場合は、起動時の表示に従ってください。箱・蓋DB画面にもリンクがあります。
外部ライブラリなしで動作します。

### 確認手順

1. サンプル設備を複製し、設備IDと名前を変更する。サンプル寸法は実機仕様ではありません。
2. 「設備共通の設定」でL字本体・爪の固定寸法と、反対端から爪中心までの距離を編集する。1設備1設定で、箱ごとの登録はない。爪の開閉量・開閉による寸法変化は扱わない。
3. 「表示確認用プレビュー」で箱と対応する蓋を選択する。爪中心は、蓋込み外形の反対端から設定距離だけ戻った位置に自動配置される。
4. 335mm／503mmなどの異なる箱、4つの把持角、箱の0°／90°を切り替えて形状を確認する。
5. 本体・爪の固定寸法の干渉形状を立体・上面・側面で確認する。爪寸法は箱サイズによらず一定で、位置だけが自動計算される。
6. 「設備設定を保存」で全設備の共通形状を永続化し、「保存内容を再読込」で復元を確認する。箱・蓋・回転・把持角・視点は保存されず、これらを切り替えても未保存状態にはならない。

動作ステップ別の設定、進入・退避の高さ・オフセット、経路表示はこの段階の対象外です。

設定は [hand_profiles.json](../algorithm_programmer/hand_profiles.json) に保存されます。
入力不正時はエラーを表示し、不正な保存では既存ファイルを変更しません。
未保存の変更は設備切替時も保持され、ページ離脱・再読込時には破棄確認を行います。
保存は全設備を対象とするため、複数画面からの同時編集は避けてください。

### 座標と形状の意味

- 画面内の原点は、最終配置の蓋込み外形の最小XY・上面Z。実際のパレット上の配置位置はまだ指定しない。
- 箱ローカルX＝DBのW、Y＝DBのL。既存計算エンジンの回転0°と合わせ、キーの意味を変えない。
- 角IDは箱に固定し、90°回転後も同じ物理的な角を表す。
- 把持角から箱の内側へ直交するU/V軸を定義する。各角では剛体回転し、ハンドの鏡映はしない。
- ハンド0°はU＝パレット＋X、V＝＋Y。上から見て反時計回りが正。
- 本体の長さは箱サイズによらず固定。爪だけが辺寸法に追従する。本体長を超える爪位置は設定範囲外として表示を中止する。
- 端からの距離は爪の中心まで。U辺の爪の厚みは−V側、V辺の爪の厚みは−U側に取る。
- 本体・爪は入力した固定寸法の直方体として表示する。全方向の干渉余裕は開閉量ではなく、固定形状へ追加する余裕である。

**第1段階は設備共通の干渉形状の確認専用です。** 箱とハンドの干渉、経路途中の干渉、
配置順、ロボットの到達性・安全性は判定しません。既存の計算結果・制約判定は変更しません。
爪形状・対辺からの位置決めルールが実機に合うかを確認した後、配置位置付近の干渉判定、
配置順・把持角探索の順に進めます。経路判定は後工程とし、位置付近の判定だけで進入・退避が成立するとは扱いません。
保存済み形状を既存の配置結果へ重ねた静的干渉の確認は、
[統合ビューア](../visualizer/README.md#ハンド干渉の静的確認) に追加しています。

## 2. TP規格コンテナの体系とモジュール仕様

### 2.1 TP規格とは
自動車産業・製造業物流において標準化されたプラスチックコンテナ規格（Toyota Plastic Box / JIS準拠）です。
**基準モジュール寸法（間口 335 mm × 奥行 335 mm）** を単位とし、倍数・分数関係にある異なる型番同士でも**底面のTP格子リブ構造により相互嵌合（スタッキング）が可能**です。

### 2.2 TP規格の平面モジュール関係

```
 ┌───────────────┬───────────────┐
 │   TP-330系    │   TP-330系    │
 │ (335 x 335)   │ (335 x 335)   │  ──► 合計: 670 x 335 mm (TP-360系と完全一致)
 ├───────────────┴───────────────┤
 │           TP-360系            │
 │         (670 x 335)           │
 └───────────────────────────────┘

 ┌───────────────────────────────┐
 │           TP-360系            │
 │         (670 x 335)           │
 ├───────────────────────────────┤  ──► 合計: 670 x 503 mm (TP-460系と完全一致)
 │   TP-330系    │   TP-330系    │
 │ (335 x 335)   │ (335 x 335)   │
 └───────────────┴───────────────┘
```

| シリーズ | 外寸長さ L (mm) | 外寸幅 W (mm) | モジュール比率 | 嵌合互換性 |
| :--- | :---: | :---: | :---: | :--- |
| **TP-110系** | 168 | 168 | $0.5 \times 0.5$ | 4個で TP-330系 1個と同フットプリント |
| **TP-130系** | 335 | 168 | $1.0 \times 0.5$ | 2個で TP-330系 1個と同フットプリント |
| **TP-330系** | 335 | 335 | $1.0 \times 1.0$ | **基準モジュール** |
| **TP-340系** | 503 | 335 | $1.5 \times 1.0$ | 2個で TP-490系(1005x335) や 340系2列(503x670)と整合 |
| **TP-360系** | 670 | 335 | $2.0 \times 1.0$ | TP-330系 2個の上/下に嵌合段積み可能 |
| **TP-460系** | 670 | 503 | $2.0 \times 1.5$ | TP-360系(2x1) + TP-130系(2x0.5) や TP-340系(1.5x1) 2個とモジュール整合 |
| **TP-480系** | 838 | 503 | $2.5 \times 1.5$ | 特大モジュール |
| **TP-490系** | 1005 | 503 | $3.0 \times 1.5$ | 1200x1000 パレットの短辺(1000mm)にジャストフィット |

### 2.3 高さ体系と嵌合深さ (fitting_depth)

TP規格の高さは規格化されており、異なる高さの箱を組み合わせても段積み全体の高さを揃えやすくなっています。

- **代表的外寸高さ**:
  - **1型 (浅型)**: 103 mm
  - **1.5型 (中浅型)**: 149 mm
  - **2型 (標準型)**: 195 mm
  - **3型 (深型)**: 288 mm
- **嵌合深さ (`fitting_depth`)**:
  - TP-110 / 130系: **8.0 mm**
  - TP-330 / 340 / 360 / 460 / 480 / 490系: **10.0 mm**
- **段積み総高さの計算式**:
  $$H_{total}(N) = H_{bottom} + \sum_{k=2}^N (H_k - fitting\_depth_k)$$

### 2.4 側面リブ厚み (`rib_thickness`) の定義と計算

コンテナの「側面リブ厚み」は、樹脂単板の板厚ではなく、**外周フランジ・補強リブ構造を含めた片側側壁の総厚み**として定義されます。

$$\text{側面厚み} = \frac{\text{外寸} - \text{有効内寸}}{2} \quad (\text{または} \quad \frac{\text{外寸} - \text{内寸}}{2})$$

- **TP規格箱**:
  - 外寸 335mm に対し内寸 300mm / 有効内寸 291mm $\implies$ 片側側面厚み **約 17.5mm 〜 22.5mm**（代表値 **22.0mm**）
  - 全てのTPシリーズで側壁リブ・フランジ厚みがほぼ共通規格（22.0〜22.5mm）となっています。

## 4. パレット (1200x1000) への適合性考察

1. **TP-340系 (503 × 335 mm)**:
   - 長辺 1200mm に対して $503 \times 2 = 1006\text{ mm}$、または $335 \times 3 = 1005\text{ mm}$、$335 \times 4 = 1340\text{ mm}$（1360mm未満許容枠内！）。
  - 短辺 1000mm に対して $335 \times 3 = 1005\text{ mm}$ や $503 \times 2 = 1006\text{ mm}$ は、いずれも許容スパン $1100\text{ mm}$ 未満。安定性の下限 $800\text{ mm}$ も満たす配置を選定する。
2. **TP-360系 (670 × 335 mm) & TP-460系 (670 × 503 mm)**:
   - 長辺 1200mm に対して $670 \times 2 = 1340\text{ mm}$（**長辺1360mm未満の許容枠を最大限に活かしたジャストフィット配置**が可能！）。
  - 短辺 1000mm に対して $503 \times 2 = 1006\text{ mm}$、または $503 + 335 = 838\text{ mm}$ は、いずれも $800\text{ mm} \le Y_{span} < 1100\text{ mm}$ を満たす。
3. **OC-50L (530 × 366 mm)**:
  - 長辺 1200mm に対して $530 \times 2 = 1060\text{ mm}$、短辺 1000mm に対して $366 \times 2 = 732\text{ mm}$（800mm未満のため単独列は工夫が必要）または $530 + 366 = 896\text{ mm}$（800mm以上1100mm未満に適合）。

## 5. 蓋データベース仕様（Phase 2 新規追加）

### 5.1 蓋DB の位置づけ

- **ファイル**: `box_research/lid_db.json`
- **目的**: パレタイズ対象箱に対応する蓋（フタ）の仕様を一元管理
- **用途**:
  - テストケース生成時の蓋選択肢の提供
  - パレタイズ結果への蓋情報付加（将来拡張）
  - UI上での箱-蓋関連性の可視化

### 5.2 蓋データ項目

各蓋について以下を管理：

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `id` | string | 蓋識別子（例: `"LID-001"`） |
| `name` | string | 蓋の名称（例: `"TP-330系対応クリア蓋"`） |
| `type` | string | 蓋の規格タイプ（例: `"TP"`, `"OTHER"`） |
| `width` | float | 蓋の幅 [mm] |
| `length` | float | 蓋の奥行き [mm] |
| `thickness` | float | 蓋の厚み [mm] |
| `fit_type` | string | 蓋の嵌め方：`"外嵌め"` \| `"内嵌め"` \| `"なし"` |
| `description` | string | 対応規格や特徴の説明 |

**fit_type の定義**:
- `"外嵌め"`: 箱外側面と蓋で位置決め（標準方式、9個の蓋）
- `"内嵌め"`: 箱内壁面と蓋で位置決め
- `"なし"`: 蓋を使用しない場合（universal option、LID-010）

### 5.3 箱と蓋の互換性管理

Phase 2 で箱DB（`box_db.json`）を拡張し、各箱に `compatible_lids` フィールドを追加：

- **フィールド**: `compatible_lids` (array of string)
- **内容**: 当該箱に対応する蓋IDリスト
- **例**: 
  ```json
  {
    "id": "TP-331",
    "name": "TP-331コンテナ",
    ...
    "compatible_lids": ["LID-001", "LID-002"]
  }
  ```
- **全体方針**: `compatible_lids` には箱に対応する実蓋のみを登録する。蓋DBの `type: "NONE"` は全箱共通の選択肢として扱い、箱ごとの互換リストには登録しない。

| ファイル | 説明 |

### 5.5 技術的ハイライト

- **REST API**: `serve_viewer.py` に蓋DB用エンドポイントを実装
  - `GET /api/lids` — 蓋DB全体を取得
  - `POST /api/lids/save_all` — 蓋DB全体を保存
- **UI**: HTML5 + Tailwind CSS で蓋管理画面を実装
  - 蓋統計（総数、外嵌め数、内嵌め数）を表示
  - 蓋の追加・編集・削除をモーダルフォームで実行
  - fit_type をドロップダウンで選択
- **データ永続化**: UTF-8 JSON ファイルとして直接保存（DB エンジン不要）

### 5.6 蓋の色情報（任意）

- `color` は「黒」「青」「透明」などを記録する任意の文字列項目。未設定は空文字 `""` とする。
- 蓋一覧の「色」列と追加・編集フォームに対応。項目のない旧データも未設定として扱う。
- 保存時に色情報を保持する。色名から既存データの色を推測して設定しない。
- 現時点ではパレタイズ計算・制約検証・3Dビューアの描画色には使用しない。
