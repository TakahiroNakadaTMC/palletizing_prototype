# 品番カタログと箱・蓋・パレットDB

## 正式データ

| ファイル | 内容 |
|---|---|
| `catalog/box_type_db.json` | 品番ごとの仕入先・現場箱名称・共通箱モデル・固定蓋 |
| `catalog/box_model_db.json` | 計算に使う箱寸法、嵌合、支持点、互換蓋 |
| `catalog/lid_db.json` | 蓋の仕様 |
| `catalog/supplier_db.json` | 仕入先の数字4桁と仕入先名の対応（初期63組） |
| `catalog/skid_db.json` | KEY2ごとの仕入先、パレット、荷山上限、候補品番、更新日時・履歴 |
| `catalog/test_cases.json` | テストケースと実行対象状態 |
| `catalog/migration.json` | 過去の移行内容・旧名称対応・モデル名変更履歴の監査記録 |
| `pallet_db.json` | 物理パレット仕様。従来と同じ保存場所 |

`box_list.csv` は資料であり、運用時には読み込みません。
`catalog/migration.json` の移行元ハッシュ・旧名称対応・ケース対応表は監査記録として保持し、
現在の参照整合性判定には使用しません。モデル名変更履歴は、旧名称の再利用防止などの
現在の編集保護にも使用します。

各品番の固定蓋は品番DB、使用可能な蓋は共通箱モデルDBで管理します。
ケース（版2）には `skid_id`（KEY2）と `part_number`・`count` を保存します。
使用パレットと荷山上限はケースには保存せず、スキッドDBの
`pallet_id` と `pallet.max_x_span`・`max_y_span`・`max_height` をその都度使います。
最大Hはパレット上面からの荷物高さです。各上限は正数、LはW以上です。
未登録値は `null` で保存し、仮のパレット・寸法では補いません。

1つの品番を複数のKEY2の候補にできますが、候補品番の仕入先はスキッドと一致する必要があります。
使用中の候補品番・スキッドは削除できません。
未登録項目があればケースの新規作成・計算を止め、何が必要かを表示します。
設定変更時は関連ケースへの影響を確認してから保存し、変更前後・更新日時・関連ケースを
スキッド内の `history` に保存します。履歴は通常編集で直接書き換えられません。
CSVからの初回登録と移行前のケース設定は `migration.json` に記録しました。再生成は行いません。

### スキッドIDと仕入先対応表

IDは仕入先（数字4桁）＋工区（英数字1文字）＋出荷場（英数字3文字または空欄）＋
コース（英字1文字）の順に連結します。英字は大文字、英数字は半角に統一し、先頭0を保持します。
例：1019・4・030・J → `10194030J`、2641・3・空欄・D → `26413D`。
保存IDから4項目を一意に分解できるため、4項目の重複保存はしません。
仕入先名は数字4桁から対応表で決まり、スキッド編集画面では確認専用です。
未登録の数字は「仕入先対応表」で名前を先に登録します。使用中の対応は削除できません。

対応表の形式は `{"1019": {"id": "1019", "supplier_name": "アイシン"}}` です。
数字は文字列で保存し、同じ仕入先名に複数の数字を対応付けることは許可します。
既存数字は固定です。仕入先名の訂正は、影響する対応表・品番・スキッド・ケース・
パレットの一覧を確認してから同じ名前を一括更新します。過去の変更履歴の名前は書き換えません。

登録済みIDの変更では、保存前に変更前後のID・影響ケースを確認します。
ケースの `skid_id` も同じ保存処理で更新し、途中で失敗した場合は一式を復元します。
履歴には変更元 `previous_id` と変更先 `skid_id` を追加し、既存の設定履歴を引き継ぎます。
ID以外の設定も同時に編集可能ですが、候補品番・仕入先・パレットの参照条件は維持します。
名前訂正・ID変更も古い画面の版からの保存は拒否されます。
承認済みの `1019430J` → `10194030J` 訂正と、関連5ケースの更新は移行履歴にも記録しています。

## 編集画面

箱・蓋・品番・ケースを編集するには:

```powershell
python .\box_research\serve_viewer.py
```

既定の `/` は品番・箱モデル・蓋・パレットDB画面を開きます。ケース専用画面は `/catalog_cases.html` です。

テストケースサーバーから開く場合:

```powershell
python .\test_programmer\serve_testcase_viewer.py
```

このサーバーの既定画面はケース編集です。どちらのサーバーも同じカタログAPIと保存先を使います。

編集内容は「変更をまとめて保存」で保存します。複数画面から同時に編集した場合、古い版からの保存は拒否されるため、再読み込みして変更内容を確認してください。
保存処理はカタログ一式をロック下で照合し、内容が変わったファイルだけを更新します。
途中で失敗した場合は更新済みファイルを復元します。
カタログの版番号にはスキッドDB・パレットDBも含まれます。LF/CRLF の差は版番号に影響しません。
仕入先対応表も版番号と保存失敗時の復元の対象です。
他の人からDBを受け取る場合は差分を比較して統合してください。
スキッドDBだけの受け渡しは、双方が対応プログラムを使い、参照先の品番・パレットが存在する場合に可能です。
新しい参照先を追加した場合はそのDBも必要です。
ID変更はケースとスキッドDB、新規の仕入先は対応表も一緒に受け渡します。
仕入先名の訂正では、影響する対応表・品番DB・スキッドDB・ケース・パレットDBをまとめて渡してください。

パレットDBの利用仕入先名は、承認された正式名称「ファインシンタ」「臼井国際産業」
「椿本チェイン」に統一しました。品番DB・仕入先対応表と同じ名前でパレット適合性を判定します。
パレットの型番・本体寸法・スキッドの選択済みパレットや荷山上限は変更していません。

現在のケースから参照されている品番・パレットは削除できません。品番が使う箱モデル・固定蓋、モデルが互換蓋として使う蓋も削除できません。使用中のモデルを通常保存で参照と同時に削除することもできません。パレットの削除・寸法・利用仕入先変更は、ケースとの整合性をサーバーで再検証します。パレット本体は長さLが幅W以上である必要があります。利用可能な仕入先は1行に1件入力します。標準パレットは固定です。モデル名の変更は影響する品番・ケースを表示して確認した後に保存し、旧名称の再利用を防ぎます。移行情報と名前変更履歴は通常保存では変更できません。

旧DB・ケースAPIへの書き込みは `410 Gone` で明示的に拒否します。旧画面のブックマークは新しい編集画面へ転送されます。
