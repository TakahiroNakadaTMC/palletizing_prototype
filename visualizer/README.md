**担当エージェント:** `visualizer`  
**対象読者:** `orchestrator`, `tester`, `supervisor`, `algorithm-programmer`

## 1. 概要

本ディレクトリは、パレタイズアルゴリズムが出力した荷姿結果データ（配置座標、回転、積み順、支持関係）を Web ブラウザ上で直感的に確認・検証できる **Three.js ベースの3Dインタラクティブ可視化ツール** を提供します。

---

## 2. ツール構成

```text
visualizer/
├── visualize.py          # スタンドアロン3D HTML生成スクリプト
├── index.html            # 統合3Dビューワ Webフロントエンド
├── serve_3d_viewer.py    # 統合3Dビューワ用ローカルHTTPサーバー
└── README.md             # 本ドキュメント
```

---

## 3. 主な機能と特徴

1. **リアルタイム 3D レンダリング**:
   - パレット（$1200 \times 1000 \times 144\text{ mm}$）およびガイドライン枠（最大積載高 $1200\text{ mm}$、長辺許容幅 $1360\text{ mm}$ 点線）の描画。
   - 箱型番ごとの自動カラーパレット色分け、エッジワイヤーフレーム強調。
   - 積み順番号と型番の 3D スプライトラベル表示。

2. **積み順 Step-by-Step コントロール**:
   - **タイムラインスライダー**: 1箱目から全箱配置までを自由にスライド確認。
   - **自動再生 / 一時停止**: 積み上げ工程をアニメーション再生（再生速度: 0.5x, 1x, 3x）。

3. **視点操作 & プリセットカメラ**:
   - マウスドラッグによる 360 度自由回転、パン、ズーム（OrbitControls）。
   - ワンクリック視点切替（俯瞰 ISO、上面 Top、正面 Front、側面 Side）。

4. **箱詳細インスペクタ**:
   - 3D 空間上の任意の箱をクリックすると、型番、配置座標 $(X, Y, Z)$、外寸、回転角、勘合深さ、および **下段支持箱の Order 番号（`supported_by`）** を即座に表示。
5. **蓋の可視化**:
   - 蓋厚を箱本体の高さから分離し、蓋を黄系の薄いスラブとして描画。
   - 外嵌め蓋の幅・奥行きと箱中央位置を描画に反映し、箱をクリックすると蓋ID・寸法・厚さ・嵌め方を表示。
   - 統合ビューワとスタンドアロンHTMLの両方に対応。
6. **投入数と未配置理由**:
   - ヘッダーに「配置数 / 投入総数」と未配置数を表示。
   - 未配置一覧に箱型番、数量、配置できなかった理由を表示。
7. **制約検証結果**:
   - 合否バッジに加えて、結果データに含まれる制約違反理由を右側パネルに表示。
   - 未配置理由とは別に表示し、どの制約で不合格になったか確認可能。

## 4. 起動・利用方法

### (1) 統合ビューワサーバーの起動（推奨）

```bash
python3 visualizer/serve_3d_viewer.py
```
ブラウザで `http://localhost:8082` を開くと、`tester/results/` にある全テスト結果をプルダウンで切り替えて 3D 荷姿を確認できます。

### ハンド干渉の静的確認

通常の配置エンジンの積み順決定にハンド静的判定を組み込みました。新しく生成する結果の `order` は
層固定・把持角座標優先のデパレタイズ逆順を再検証した正式な配置順です。
別ファイルの保存やビューアでの手動再生成は不要で、「結果の配置順」と通常のステップ操作で確認できます。
読み込み時に検証済み結果と使用設備を表示し、箱詳細には保存済みの把持角XYZとハンド姿勢を表示します。
保存済み把持情報がある箱は、通常の配置順でも橙色のハンド立体形状と紫の把持基準点を自動表示します。
拡張余裕は半透明の黄色、基準点ラベルには箱番号とハンド向きを表示します。
ステップ操作では配置した箱、表示中の箱を選択した場合はその箱の把持角が対象です。ステップ0では表示しません。
これは保存結果に含まれるハンド形状・座標の表示であり、設備設定の変更後に再判定した表示ではありません。
旧結果にはハンド形状が含まれないため、配置エンジンを再実行してください。
手動干渉確認は現在選択した設備での追加確認であり、保存時の設備設定を変更するものではありません。

以前の結果にはこの情報がありません。自動変換はせず、CLIまたはテストランナーで再実行してください。
ハンド順序生成が停止した場合はCLIが失敗し、正式な結果として保存しません。
既存ファイルは上書きせず残るため、失敗した実行で表示中の過去結果が更新されたとは扱わないでください。

既存の配置位置・順番を変えずに、各箱の配置時点で固定形状のハンドが干渉するか手動確認できます。
ハンド形状は [設備共通設定](../box_research/README.md#ハンド設定形状確認第1段階) で保存したものを使用します。
設定画面の移設やロボット向け出力は今回の対象ではありません。

1. `python visualizer\serve_3d_viewer.py` で起動する。起動済みなら再起動し、ブラウザで `Ctrl + F5`。
2. 上部でテスト結果を選択する。
3. 左側の「配置結果・把持角の確認」で「別の設備・把持角で再確認（手動）」を開き、設備・対象箱・把持角を選択する。
4. 「配置時点の干渉を確認」を押す。対象箱まで表示され、対象より後の箱は非表示となる。
5. 橙のハンド形状、紫の把持角、赤い干渉相手と重なり範囲を確認する。
6. 別の角を選んで再確認する。形状がその箱・角に対応しない場合は、干渉なしではなく設定範囲外エラーとなる。
7. 「手動判定表示を解除」またはタイムライン操作で手動判定表示を解除する。保存済み把持角の点表示は残る。

設備設定を別画面で変更・保存したら、「設備設定を再読込」して再判定してください。
設備・箱・角・結果・表示ステップを変えると古い判定を解除し、前の結果を新条件の判定として表示しません。

判定仕様:

- 結果JSONの箱・蓋寸法・座標を使用し、現在のDBで過去結果を上書き解釈しない。
- 現行の蓋込み最小XY・上面Z形式と、座標基準フィールドのない従来の本体底面形式に対応。
- 無蓋（`lid_fit_type: "なし"`、蓋厚0）の蓋寸法 `0 × 0` は正常として扱い、箱本体の外形で判定する。実際の蓋がある場合は正の蓋寸法が必要。
- 対象より小さい `order` の箱と蓋だけを障害物にする。蓋と本体は別の直方体として判定する。
- パレットはXY外形内・上面Z=0以下の中実領域として保守的に判定する。脚や空洞の形状は扱わない。
- 本体・爪の固定形状に追加の干渉余裕を付けて判定し、実形状の重なりと「余裕不足」を区別する。
- 余裕を含む形状がちょうど接する境界は重なりとしない（数値許容差 `1e-7 mm`）。
- 把持対象への接触は許容し、対象自体には追加余裕を適用しない。実際の食込みがあれば別途報告する。
- 箱同士の嵌合許容量はハンドへ適用しない。既存の荷姿制約の合否は変更しない。

**配置位置での静的判定のみです。** 進入・下降・寄せ・解放・退避の経路、ロボットの到達性・関節姿勢は未判定です。
「干渉なし」は配置可能・安全の保証ではありません。手動判定で保存済みの把持情報を書き換えません。
元の配置結果ファイルは読取専用で、確認操作によって更新されません。

### 正式な配置順を確認するUIへ整理

順序生成は配置エンジンで実施するため、ビューアの「全箱の把持角を自動選択」
「デパレタイズ順から配置順を生成」、元順・生成順の切替、比較一覧・4角候補一覧は削除しました。
ビューアは結果JSONに保存された正式な順番だけを表示します。旧結果は再実行が必要なことを明示します。
手動の再確認は補助操作として折りたたみ、保存時の設備と再確認用設備を区別します。
使っていないThree.js・OrbitControlsの読み込みも削除し、既存のCanvas描画を維持しています。

層固定・把持角座標による優先順位・失敗時の出力抑止は配置エンジン側で維持しています。
詳しい生成規則は [アルゴリズムの説明](../algorithm_programmer/README.md#正式な配置結果への組み込み) を参照してください。

検証:

```powershell
$env:HAND_VIEWER_BROWSER_TEST = '1'
python -m unittest algorithm_programmer.hand_sequence_test algorithm_programmer.hand_selection_test algorithm_programmer.hand_collision_test visualizer.hand_inspection_test -v
```

Edgeを使う画面テストはCDNにアクセスせず、一時データ・サーバー・専用ブラウザープロファイルで実施します。
描画ロジックとAPI操作を検証するもので、CDNから読み込むスタイルの見た目の検証ではありません。

### (2) スタンドアロン HTML の個別生成

```bash
python3 visualizer/visualize.py tester/results/result_mixed_tp_same_height.json -o visualizer/viewer.html
```
生成された `visualizer/viewer.html` をブラウザで直接開いて確認できます。
